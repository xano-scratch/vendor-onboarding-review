Vendor Onboarding Review

A governed procurement backend that risk-tiers each vendor from one versioned rule set, derives the approvals that tier needs, and blocks completion at the API layer until every required approval is granted by the right role.

5 tables · 13 endpoints · 6 screens · auth: @xano-sdk/auth

What it proves

This is the governed backend under a plausible AI-built vendor-onboarding tool, made safe to run in production. The business logic lives in one readable API layer. A reviewer can open the completion endpoint and see exactly why a high-risk vendor needed an admin sign-off, and why an incomplete case was refused.

One rule set

A versioned scoring table decides a vendor's risk tier. The rule lives in exactly one place, called by both submit and rescore.

Derived approvals

The tier derives the approvals the case needs. High risk adds an admin step the lower tiers never see.

An API-layer gate

Completion is refused, with an audit line, until every required approval is granted. The gate holds even through an agent's request.

A minute with it

  1. Open the link and continue as Morgan (admin).
  2. Open the Review board: cases by stage, a high-risk case flagged, one with an agent draft waiting.
  3. Open the high-risk case. It needed three approvals (two approvers and one admin). Press Complete: the API-layer block appears, because a step is still pending, and a block line is written to the trail.
  4. Open a second window as Avery (approver) and approve the pending step. Watch it arrive live in Morgan's board, with no reload.
  5. As Morgan, approve the admin step, then Complete. The case moves to Approved, and the trail shows the whole sequence.
  6. Switch to Riley (requester): only your own submissions, with no Approve or Complete. The role difference is enforced by the API.

Use this template

Clone it, then run it on your machine with no account, or on a cloud link for ChatGPT and Claude.

git clone https://github.com/xano-scratch/vendor-onboarding-review
cd vendor-onboarding-review
npm install
npm run xano:deploy    # deploys and seeds on the Xano Engine on your machine
npm run dev            # opens the app, then click "Continue as Morgan"

For a cloud link that works with ChatGPT and Claude connectors:

npx xanosdk login
npm run xano:deploy:ephemeral

API surface

Every domain endpoint is under api:onboarding/* and needs a signed-in token. Access is checked per endpoint by role, not by row-level security.

VerbPathWhoEnforces
GET/queueapprover, adminThe queue with each case's outstanding count
GET/submissions/minesigned inThe caller's own cases only
GET/submissions/{id}owner or reviewerOne case; 404 if not yours and you can't read all
POST/submissionsrequester+Scores the vendor, derives the tier's approvals
POST/submissions/{id}/approvals/{approval_id}/approverole matches the stepAdvances the case, writes an approve event
POST/submissions/{id}/completeadminThe gate: refuses until every approval is granted
POST/rules/activateadminPublishes a new rule version, retires the prior one

Works with your agent

A permissioned MCP server exposes the app's jobs, so an agent works the queue under the same rules a person does. Each agent gets its own scoped, expiring, revocable key, and every call is logged.

  • list_review_queue, get_case, score_preview (read)
  • submit_vendor (the person's own routine intake)
  • approve_step, complete_case (drafted for a person to approve in the app)
